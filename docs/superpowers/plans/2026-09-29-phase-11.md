# Phase 11 Approval Router Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Route exact canonical pending action approvals safely and integrate their
durable decisions with the existing Controller/Mock adapter lifecycle.

**Architecture:** A separate approvals package owns typed facts, pure classification
and policy, and private atomic audit records. Optional canonical approval observation
is adapter-owned; Controller alone dispatches approval responses with durable intents.

**Tech Stack:** Python 3.11+, existing Pydantic 2, pathlib, SHA-256, existing JSON storage;
no additional dependencies.

**Spec:** ../specs/2026-09-29-phase-11-design.md and the current user Phase 11 attachment.

## Global Constraints

- Only Phase 11; no Phase 12/13 implementation, external network or credentials.
- Canonical ApprovalRequest/RiskLevel and existing six schemas remain unchanged.
- LOW is not automatic permission; unknown actions never auto-allow.
- External/manual review is the real repository's authority; no PASS tag or merge.
- Execute fixture Controller/Version/Recovery mutations only in temporary repositories.

## Review Focus

- A request/resource changes after response intent: detect it before adapter response.
- A decision persists but response acknowledgement does not: never blindly resend.
- Optimistic LOW plus destructive facts: escalate and require human/deny.
- Command/prompt/metadata contain secrets: audit/presentation retain hashes only.
- Pending approval is cancelled or session disappears: never resume a replacement run.
