# Phase 08 Recovery Manager Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans with native execution and TDD.

**Goal:** Provider-neutral, persistent, safe operational recovery.
**Architecture:** Read-only inspect, explicit journaled plan/execute, VersionManager mutation authority.
**Tech Stack:** Python 3.11+, existing Pydantic and atomic JSON storage; no new dependencies.
**Spec:** docs/superpowers/specs/2026-09-27-phase-08-design.md

## Global Constraints

- Phase 08 only; schemas/canonical models unchanged; fixture repositories for mutations.
- Preserve unknown edits and previous stable tags; no destructive Git operations.
- StateManager owns state transitions; VersionManager owns Git/ref/worktree checks.

## Review Focus

- Old plans after content/index/ref/ownership changes must refuse execution.
- Legacy locks, PID ambiguity and remote ownership must never trigger cleanup.
- Missing/corrupt publication intent cannot authorize metadata reconstruction.
- Dirty work attributed at heartbeat must not hide later unknown changes.
- Partial state/journal publication must remain observable and restart-safe.

## Tasks and verification ledger

1. Private recovery contracts, classifier, journal and heartbeat/liveness.
   - Write malformed/round-trip/classification tests; run red before implementation.
   - Implement strict typed contracts and atomic persistence; run green.
2. VersionManager publication intent and owner-aware lock primitives.
   - Write partial publication and active/dead/unknown-lock tests; run red.
   - Add intent-before-ref publication and explicit guarded reconciliation; run green.
3. RecoveryManager inspect/plan/execute, continuation and isolated restore.
   - Write fixture integration tests for interruption, ownership, provider waits, changed
     preconditions, restart/idempotency and restore. Run red, implement, run green.
4. Whole-branch safety review, documentation, regression and manual handoff.
   - Run full suite and all requested subsets, CLI/Ruff/pip/six schema checks.
   - Update CURRENT_STATE to AWAITING_REVIEW/PENDING; inspect diff; attempt commit.

Execution rulings and test outcomes are recorded in PHASE_08_EVIDENCE.md. One coherent
implementation attempt commit and optional documentation handoff; no PASS tag or merge.
