## Decisions

Project definitions remain separate from the four canonical communication roots.
Reuse shared structural validation/primitive types without changing Phase 01.
Project/phase collections use immutable tuples. PROJECT.yaml requires version 1.0,
identity/workspace, controller, generic agent IDs, nonempty phases/objectives/criteria.
Optional dependency lists default empty, criterion required defaults true, controller
revision limit defaults three. Reject extra fields, duplicate IDs/keys and invalid graphs.
Use safe PyYAML parsing because the standard library has no YAML parser.
Resolve relative workspaces against PROJECT.yaml's parent, without creating/executing them.

Ruling: dependency order uses declaration order to break ties — deterministic without
assuming numeric IDs or forcing textual declaration to be topological.
Ruling: use the twelve blueprint statuses and only the transitions explicitly requested.
Terminal states have no outgoing transitions. Same-status explicit transitions fail.
Ruling: phase completion is an explicit state operation, not review/gate evaluation;
no automatic next-phase selection/execution. Completion history cannot be removed.
Ruling: counters distinguish provider_retry, phase_revision and review_retry. A phase
revision increments current_attempt and resets transport/review counters; only revisions
enforce max_phase_retries. No retry scheduling or provider behavior is implemented.
Ruling: persistence is single-writer — no locking/recovery framework in this phase.
Write UTF-8 JSON to a unique sibling temp file, flush/fsync then os.replace. Readers
see complete old/new data. This does not promise durability against hardware power loss.
Corrupt/missing state raises StateError and is never silently reinitialized.
Revalidate definitions/state/canonical last_review at manager boundaries.
